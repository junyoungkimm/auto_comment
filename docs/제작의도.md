# 제작 의도

> **고민이 가장 뜨거운 순간에, 그 고민을 정확히 짚는 한 줄로, 운명원을 떠올리게 한다.**

연애 상담 영상의 댓글창은 같은 고민을 가진 사람들이 모이는 곳입니다. 광고 배너는 건너뛰지만, 내 얘기 같은 댓글에는 멈춥니다. 이 대시보드는 그 한 줄을 **영상마다 다르게, 근거 있게, 규칙 안에서** 만들어 게시하는 마케팅 에이전트입니다.

---

## 1. 마케팅 전략 — 무엇을 노리는가

### 타깃: 지금 막 고민을 꺼낸 사람

연애 고민 영상을 끝까지 보고 댓글창까지 내려온 시청자는 이미 문제를 인식하고 답을 찾는 중입니다. 퍼널로 보면 **관심 단계를 건너뛴 고관여 고객**입니다. 그래서 채널을 넓게 뿌리기보다, **연애 고민을 다루는 영상만** 골라 들어갑니다(4-2).

### 타이밍: 뜨기 직전의 영상

댓글은 먼저 자리 잡을수록 오래 노출됩니다. 이미 수십만 회가 나온 영상에는 수천 개의 댓글이 쌓여 있어 묻힙니다. 그래서 **조회수는 아직 적지만 빠르게 오르는 영상**을 찾아냅니다(4-1). 영상이 뜰 때 댓글도 같이 올라탑니다.

### 메시지: 공감 → 막막함 → 운명원

광고처럼 보이는 순간 신뢰를 잃습니다. 초안은 시청자의 말투로, 정해진 흐름을 따릅니다.

```
① 영상 속 한 장면에 대한 반응    "단호한 거절 이유부터 알아야 한다는 말 진짜 찔리네요"
② 그래서 드는 막막함             "알아도 결국 인연이면 만나는 것 같고..."
③ 운명원으로 자연스럽게 연결      "운명원 연애사주가 그렇게 잘 본다던데 나도 한번 보고 싶다"
④ 광고 표기                      "(광고)"
```

- **①이 그 영상에서만 나올 수 있는 말이어야 합니다.** 복붙 댓글은 스팸으로 읽히고, 장면을 짚은 댓글은 "같은 걸 본 사람"으로 읽힙니다.
- **③은 '들어본' 입장으로만 씁니다.** "~다던데", "~궁금하다". 써 본 척하는 후기는 쓰지 않습니다. 금지 사항이자, 들키는 순간 브랜드 신뢰가 무너지는 지점입니다.
- **④는 협상하지 않습니다.** 경제적 이해관계가 있는 추천은 표시광고법상 공개 대상입니다. 브랜드를 지키는 가장 싼 보험입니다.

## 2. 전체 구조

```
 STEP 1 영상 고르기           STEP 2 분석과 초안                  STEP 3 게시와 기록
┌──────────────────┐      ┌─────────────────────────┐      ┌────────────────────────┐
│ 채널 RSS 최신 영상 │      │ 자막 (없으면 AI가 영상 시청)│      │ 계정 배정 (고르기/순환)  │
│ 링크 직접 입력     │ ──▶ │ + 인기 댓글 상위 10개      │ ──▶ │ 계정 크롬 창 열기        │
│ '연애' 뜨는 영상   │      │ → 고민 한 줄 · 근거 장면   │      │ 한 글자씩 입력 → 게시    │
│ 연애 주제 판별     │      │ → 댓글 초안 · 규칙 검사    │      │ 내 댓글 확인 → 기록      │
└──────────────────┘      └─────────────────────────┘      └────────────────────────┘
```

| 계층 | 구성 |
|---|---|
| 화면 | 정적 HTML · JS (빌드 없음), 진행 상태를 0.5초 간격으로 받아 표시 |
| 서버 | FastAPI, `127.0.0.1` 에서만 동작 |
| AI | Gemini (JSON 스키마 고정 출력, 유튜브 영상 직접 입력) |
| 유튜브 | 공식 RSS · oEmbed (키 불필요), Data API v3 (OAuth), Playwright (계정 크롬 창) |
| 기록 | 추가 전용 JSONL — 파일 자체가 감사 로그 |

## 3. STEP 1 — 어떤 영상을 고르는가

### 3-1. 영상 수집

지정 채널의 **공식 RSS**에서 제목 · 채널 · 올린 날짜 · 썸네일 · 조회수를 가져옵니다. API 키가 필요 없어, 저장소를 받은 사람도 설정 없이 바로 실제 목록을 봅니다. 링크로 넣은 영상은 공식 **oEmbed**로 정보를 채웁니다.

### 3-2. 뜨기 직전 영상 찾기

**시간당 조회수**로 속도를 잽니다.

```
시간당 조회수 = 조회수 ÷ 올라온 뒤 지난 시간(시간)
뜨기 직전 = 조회수 1,000 ~ 5,000  AND  시간당 150회 이상     → 시간당 조회수 높은 순 정렬
```

- **채널 목록 안에서**는 RSS 조회수로 바로 계산해 `뜨는 중 · 시간당 N회`를 붙입니다.
- **[뜨는 연애 영상 찾기]**는 유튜브 전체가 대상입니다. `search.list`로 최근 48시간 · 한국 · 한국어 · '연애' 영상 50개를 받고, `videos.list`로 조회수를 붙여 같은 기준으로 거릅니다. 기준대로 **초안까지만** 만들고 게시 버튼은 잠급니다.

### 3-3. 연애 주제 판별

연애 채널에도 다른 주제 영상이 섞입니다. 엉뚱한 영상에 연애사주 댓글이 달리면 바로 광고로 읽히므로, 들어가기 전에 거릅니다.

```
점수 = Σ 강한 신호 × 2  +  Σ 약한 신호 × 1
강한 신호 (29개)  이별 · 재회 · 짝사랑 · 썸 · 읽씹 · 전남친 · 권태기 · 소개팅 ...
약한 신호 (30여 개) 심리 · 연락 · 호감 · 설렘 · 인연 · 여자 · 남자 ...
판정  2점 이상 → 연애 관련,  6점 이상 → 연애 고민
```

- 한국어는 조사가 붙으므로 **부분 문자열**로 찾습니다("남자친구가" 안의 "남자친구").
- 근거는 **제목 + 자막 앞 600자**입니다. 설명란은 쓰지 않습니다. 채널마다 붙는 고정 안내문(`#연애상담` 등)이 영상 내용과 상관없이 점수를 올리기 때문입니다.
- 걸러진 영상은 **숨기되 지우지 않습니다.** 체크 하나로 전부 볼 수 있습니다.

## 4. STEP 2 — 맥락을 어떻게 읽는가

### 4-1. 근거 자료 모으기

| 자료 | 처리 |
|---|---|
| **자막** | 한국어 우선. 각 줄에 `[m:ss]` 시각을 붙여 AI가 장면을 짚을 수 있게 함. 6,000자를 넘으면 **앞 60% + 뒤 30%**를 남김 (도입의 고민 제시와 결론이 핵심) |
| **영상 직접 보기** | 자막을 받을 수 없으면 Gemini에 유튜브 주소를 직접 넘겨 **영상을 보고 듣게** 함. 비용을 줄이려 낮은 해상도 · 앞 15분 |
| **인기 댓글** | `commentThreads.list(order=relevance)` 20개 → 좋아요 순 **상위 10개**, 150자로 정리, 내 계정 댓글은 제외. 시청자들이 어디에 반응했는지 알려주는 신호 |
| **제목 · 설명** | 자막도 영상도 쓸 수 없을 때의 마지막 근거 |

자막은 한 번 받으면 디스크에 저장하고, 새로 받을 때는 **1.5초 간격**을 둡니다.

### 4-2. 한 번의 호출로 네 가지를 만든다

Gemini에 **JSON 스키마를 고정**해 네 칸을 한 번에 받습니다. 자유 서술로 받으면 형식이 흐트러지기 때문입니다.

```json
{ "concern":         "영상이 다루는 연애 고민 한 줄 (30자 이내, 제목 베끼기 금지)",
  "quote":           "고민의 핵심이 드러나는 대사 10~35자, 원문 그대로",
  "quote_timestamp": "그 대사의 시각 m:ss",
  "draft":           "댓글 초안" }
```

프롬프트에는 1장의 **① 반응 → ② 막막함 → ③ 운명원 → ④ 광고 표기** 구조와 예시 댓글을 그대로 넣었습니다. 지켜야 할 것도 명시합니다.

- 대사를 통째로 붙이지 말고 **자기 말로 풀어** 언급할 것
- 운명원은 **들어본 입장**으로만, 개인사는 지어내지 말 것
- 링크 · 해시태그 금지, 이모지는 많아야 하나

**영상마다 다르게.** 생성 온도를 **0.9**로 높게 잡고, 근거 대사를 반드시 녹이게 해서 같은 문장이 나오지 않습니다. 같은 영상도 [다시 생성]을 누르면 새 초안이 나옵니다.

### 4-3. 근거를 검증한다

AI가 그럴듯한 대사를 지어내 "근거"로 화면에 뜨는 것을 막습니다.

```
quote 가 자막 원문에 그대로 있다          → 근거로 표시 (시각 포함)
quote 가 설명란에 그대로 있다             → 근거로 표시 (시각 없음)
영상을 직접 본 경우 + 시각이 붙어 있다     → "AI가 영상에서 들은 말"로 따로 표시
그 외                                    → 근거에서 제외
```

화면에서 **AI가 읽은 자막 원문과 인기 댓글을 펼쳐볼 수 있고**, 인용한 줄은 표시됩니다. 보는 사람이 근거를 직접 확인할 수 있습니다.

초안이 120자를 넘으면 같은 모델에 한 번 더 요청해 **브랜드 언급과 광고 표기는 남긴 채** 줄입니다.

## 5. 규칙 엔진 — 코드가 지키는 선

모든 초안은 게시 전에 아래를 통과해야 합니다. 하나라도 어기면 **게시 버튼이 꺼지고**, 버튼을 우회한 요청도 **서버가 거절**합니다.

| 규칙 | 판정 방법 |
|---|---|
| 40~120자 | 앞뒤 공백 제외 글자 수 |
| 링크 금지 | `http(s)://`, `www.`, `*.com/.net/.co.kr/.kr/.io/.me/.ly` |
| 해시태그 금지 | 공백 뒤 `#단어` |
| 후기 조작 금지 | **브랜드 언급 뒤 40자 안**에서 "가봤/받아봤/봐봤/이용해봤/다녀왔/후기/내돈내산" 등 경험 서술 탐지 |
| 광고 표기 필수 | 광고 · 홍보 · 협찬 · 유료 · 제휴 · AD 중 하나 |
| 틀에 박힌 문장 금지 | AI 없이 만든 기본 문장은 게시 불가 (사람이 고쳐 쓰면 통과) |
| 영상당 1개 | 어느 계정이든 그 영상에 게시 기록이 있으면 차단 |
| 하루 상한 10개 | **계정 합계**, 내 컴퓨터 날짜 기준 자정에 초기화 |

브랜드명 · 길이 · 상한 · 광고 표기는 전부 `.env`로 바꿀 수 있어, 다른 브랜드에도 그대로 씁니다.

## 6. STEP 3 — 어떻게 게시하는가

### 6-1. 계정 배정

```
준비된 계정 = 크롬 프로필이 있는 계정 (API 게시는 인증 토큰까지 있는 계정)
다음 계정  = 직전에 게시한 계정의 다음 차례   (계정1 → 계정2 → 계정3 → 계정1)
```

직접 고를 수도 있습니다. 계정을 늘려도 **하루 게시량은 계정 합계 10개로 고정**되고, **한 영상에는 계정 하나**만 답니다. 계정은 도달 범위를 넓히는 수단이지 물량을 늘리는 수단이 아닙니다.

### 6-2. 자동 입력 게시

Playwright `launch_persistent_context`로 **계정 전용 크롬 프로필 폴더(`--user-data-dir`)**를 엽니다. 평소 쓰는 크롬과 완전히 분리되고, 한 번 로그인해 둔 세션이 유지됩니다.

```
프로필 여는 중     계정 크롬 창을 열고 영상으로 이동 (한국어 화면 고정: --lang=ko, hl=ko)
                  댓글 영역은 지연 로딩이라 조금씩 내리며 입력창을 기다림
입력 중            입력창을 화면 가운데로 → 입력칸에 직접 한 글자씩 (고정 70ms)
                  입력이 끝나면 입력칸의 글이 초안과 정확히 같은지 확인 → 다르면 다시 입력
게시 완료          열려 있는 입력창의 [댓글] 버튼을 찾아 누름
댓글 보기          내 댓글 스레드가 화면에 뜨는지 확인 → 고유 주소(&lc=댓글ID)를 읽어 링크로 제공
기록              결과를 기록에 남김
```

- **입력 확인**이 핵심입니다. 화면에 보인 글과 실제 게시된 글이 다를 가능성을 게시 전에 없앱니다.
- 게시는 수십 초가 걸리므로 **백그라운드 작업**으로 돌리고, 화면은 진행 단계를 받아 `프로필 여는 중 → 입력 중 → 게시 완료 · 댓글 보기`를 실시간으로 표시합니다.
- 같은 프로필을 두 브라우저가 동시에 쓸 수 없으므로 **한 번에 하나만** 진행합니다.
- 입력 속도는 고정입니다. 자동화 흔적을 숨기거나 속도를 흔드는 등 **플랫폼 감지를 피하는 기능은 넣지 않았습니다.**

### 6-3. 게시 확인 — 이중 검증

화면에서 보인 것만으로 성공을 선언하지 않습니다. 계정에 공식 API 권한이 있으면, 게시 직후 **그 계정이 그 영상에 단 같은 글**을 `commentThreads.list`로 다시 찾아 **공개 댓글로 조회될 때만** `내 댓글 확인됨`을 표시합니다. 조회되지 않으면 경고를 띄웁니다.

### 6-4. 공식 API 게시

`commentThreads.insert`로 바로 게시하는 방식도 함께 제공해 화면에서 고를 수 있습니다. 화면 구조가 바뀌어도 운영이 멈추지 않는 예비 경로입니다.

## 7. 안정성 설계

| 상황 | 동작 |
|---|---|
| AI 모델이 과부하 · 한도 초과 · 사용 불가 | 대체 모델을 **차례로** 시도 (`gemini-3.5-flash → 2.5-flash → 3.5-flash-lite`) |
| AI를 전혀 쓸 수 없음 | 규칙 기반 분석기로 화면은 계속 동작, 단 그 초안은 **게시 차단** + 이유 표시 |
| 자막을 받을 수 없음 | AI가 영상을 직접 봄 |
| 게시 실패 | 이유를 사람이 읽을 말로 바꿔 표시 + **실패 순간 화면 캡처**를 기록에 첨부 |
| 게시 버튼을 누른 뒤 확인 실패 | API로 다시 찾아 실제로 달렸으면 '게시'로 기록 (같은 영상 중복 게시 방지) |
| 화면 파일 캐시 | 대시보드 파일은 캐시하지 않아 항상 최신 화면 |

## 8. 기록 — 무엇을 남기는가

```json
{ "ts": "2026-11-25T19:59:12+00:00", "video_id": "…", "video_title": "…",
  "profile": "계정1", "comment": "…", "status": "posted | failed",
  "method": "typing | api", "error": "…", "screenshot": "fail-….png" }
```

**언제 · 어느 영상에 · 어느 계정으로 · 무슨 댓글을 · 성공/실패**를 한 줄씩, 지우지 않고 추가만 합니다. 화면의 기록 패널은 계정마다 색을 달리해 배정이 한눈에 보이고, 실패에는 사유와 화면 캡처 링크가 붙습니다. 하루 상한과 영상당 1개 규칙도 이 기록에서 계산합니다.

## 9. 운영 원칙

이 도구의 성과는 **댓글 수가 아니라 운명원에 대한 신뢰**로 측정돼야 한다고 봤습니다. 그래서 물량과 속도보다 아래를 먼저 코드로 고정했습니다.

- 광고임을 밝힌다
- 써 보지 않은 것을 써 본 척하지 않는다
- 한 영상에는 한 계정, 하루 10개
- 플랫폼의 감지를 피하는 기능은 만들지 않는다
- 사람이 초안을 보고 고른 뒤 게시한다

같은 규칙 안에서 브랜드 · 타깃 키워드 · 상한만 바꾸면 다른 캠페인에도 그대로 쓸 수 있습니다.

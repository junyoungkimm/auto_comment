# 제작 의도

## 무엇을 만들었나

내 컴퓨터에서 실행하는 3칸 대시보드입니다.

```
STEP 1 영상              STEP 2 분석과 초안                STEP 3 댓글 달기
채널 최신 영상       →   자막(없으면 AI가 영상을 직접 봄)  →  계정 자동 배정 (계정1~3)
링크 직접 입력           + 인기 댓글을 읽고 고민 한 줄      계정 크롬 창이 열리고
뜨는 연애 영상 찾기      장면 인용 + 댓글 초안              한 글자씩 입력 → 게시
                         규칙 실시간 검사                   내 댓글 확인 → 기록
```

아래는 만들면서 내린 판단과 근거입니다. 전부 실제로 돌려보고 확인한 내용이며, 시연 녹화 리허설에서 드러난 문제와 고친 과정도 함께 적었습니다.

---

## 1. 영상 목록은 공식 RSS로, 키워드 검색만 Data API로

처음엔 YouTube Data API로 목록을 가져오려 했습니다. 그러면 **심사자도 본인 API 키를 발급해야** 프로그램이 돕니다.

유튜브 공식 채널 RSS에 과제 ①이 요구한 항목이 전부 들어 있었습니다.

```
https://www.youtube.com/feeds/videos.xml?channel_id=...
videoId · 제목 · 채널 · 올린 날짜 · 썸네일 · 조회수      (키 불필요)
```

조회수가 들어 있어 **시간당 조회수**도 계산됩니다. 링크 직접 입력은 공식 oEmbed로 제목·채널·썸네일을 채웁니다. 역시 키가 필요 없습니다.

다만 가점 항목 **"'연애' 키워드로 뜨기 직전 영상 찾기"** 는 지정 채널 밖, 유튜브 전체가 대상이라 RSS로는 안 됩니다. 이것만 `search.list`(최근 48시간, 한국어, '연애')로 찾고 `videos.list`로 조회수를 붙인 뒤 같은 기준(조회수 1,000~5,000 · 시간당 150 이상)으로 거릅니다. 한 번 찾는 데 약 101유닛, 하루 한도(10,000)의 1% 입니다.

과제 문구가 **"초안까지만"** 이라 검색으로 찾은 영상은 게시 버튼을 막고 `초안 전용` 표시를 붙였습니다. 서버도 한 번 더 거절합니다.

## 2. 게시: 공식 API로 시작했다가, 한 글자씩 입력하는 방식을 되살렸습니다

### 처음엔 공식 API로 갔습니다

안내서대로 Playwright `launchPersistentContext` / `--user-data-dir`로 전용 프로필을 열었는데, **구글이 자동 제어 중인 브라우저에서의 로그인을 거부했습니다.** 그래서 게시를 유튜브 공식 엔드포인트 `commentThreads.insert`로 바꿨습니다.

### 다시 확인해 보니, 막힌 건 '로그인 단계'뿐이었습니다

전용 프로필을 **일반 크롬**(`--user-data-dir`)으로 열어 사람이 직접 로그인해 두면, 이후 Playwright가 같은 프로필을 열어도 **로그인이 유지됐습니다.** 댓글 입력창도 한국어로 정상으로 떴습니다. 그래서 안내서 그대로의 흐름을 만들었습니다.

```
[댓글 달기]
  → 배정된 계정의 크롬 창이 열린다              프로필 여는 중
  → 댓글 창에 한 글자씩 입력한다 (고정 속도)    입력 중
  → [댓글] 을 누르고 내 댓글이 보이는지 확인     게시 완료 · 댓글 보기
  → 기록에 남긴다                                기록
```

공식 API 게시는 **두 번째 방식으로 그대로 남겨** 화면에서 고를 수 있습니다(`자동 입력 게시` / `API 바로 게시`). 화면 구조가 바뀌어 입력 게시가 깨져도 운영이 멈추지 않게 하기 위해서입니다.

### 하지 않은 것: 감지 우회

입력은 **고정 속도**로만 하고, 자동화 흔적을 숨기거나 속도를 무작위로 흔드는 기능은 넣지 않았습니다. 화면에 보이게 치는 것과, 플랫폼의 감지를 피하는 것은 다른 일이라고 봤습니다.

### 리허설에서 겪고 고친 것

| 겪은 일 | 원인 | 대응 |
|---|---|---|
| 입력은 됐는데 게시 버튼을 못 눌러 실패 | 입력칸을 좌표로 다시 클릭하다 다른 요소에 맞아, 입력칸이 빈 채로 접힘 | 입력칸에 직접 입력하고, **게시 전에 입력한 글이 그대로 들어갔는지 확인**. 어긋나면 지우고 한 번 더, 그래도 안 되면 게시하지 않고 실패로 기록 |
| 첫 글자 몇 개가 사라짐 | 입력칸이 막 열린 직후 초기화 | 잠깐 기다렸다 입력 |
| 화면에선 "확인됨"인데 남들에겐 안 보임 | 유튜브가 숨긴 댓글도 **작성자 화면에는 잠깐 보인다** | API 토큰이 있으면 **공개 댓글로 조회될 때만** 확인됨으로 표시. 아니면 경고 |
| 계정 창이 이미 열려 있으면 실패 | 같은 프로필을 두 브라우저가 못 씀 | "이 계정의 크롬 창이 이미 열려 있습니다"로 알려 주고, 실패·화면 캡처를 기록 |

게시 버튼을 누른 **뒤에** 문제가 생기면 실제로 달렸을 수 있습니다. 그때는 API로 다시 찾아보고, 찾으면 '게시'로 기록합니다. 그래야 실패로 잘못 기록되어 같은 영상에 두 번 다는 일이 없습니다.

## 3. 계정 배정: 고르기 또는 영상마다 돌아가며

계정1~3 중 직접 고르거나, **직전에 게시한 계정의 다음 차례**로 자동 배정합니다. 준비가 안 된 계정(크롬 프로필 없음, 또는 API 게시인데 토큰 없음)은 `(준비 안 됨)`으로 표시되고 배정에서 빠집니다.

배정과 상관없이 지키는 것이 있습니다.

- **한 영상에는 계정 하나만.** 어느 계정이 달았든 그 영상은 막힙니다.
- **하루 상한은 계정 합계 기준.** 계정을 늘려도 게시량은 늘지 않습니다.

계정을 실제로 붙여 보니 **브라우저에 로그인된 계정과 API 토큰의 계정이 다른 상태**가 있었습니다(계정1 창은 다른 채널, 토큰은 다른 채널). 게시 후 API로 대조하는 단계가 이 어긋남을 드러냈고, 두 채널을 맞춘 뒤 진행했습니다.

## 4. 자막이 막히면 AI가 영상을 직접 봅니다

자막은 키 없이 받을 수 있지만, 연속으로 요청하면 **유튜브가 IP를 차단**합니다. 실제로 걸렸고, 몇 시간이 지나도 풀리지 않았습니다. 자막이 없으면 근거로 짚을 장면이 사라져 '맥락 이해'가 약해집니다.

제미나이 API는 **공개 유튜브 영상 주소를 직접 입력**으로 받습니다. 영상은 구글 쪽에서 가져가므로 우리 IP 차단과 무관합니다.

- 자막이 있으면 자막을 씁니다 (글자 그대로 대조할 수 있어 더 정확).
- 자막이 없으면 영상 주소를 넘깁니다. 토큰을 아끼려고 **낮은 해상도 · 앞 15분**만 봅니다.
- 이때 근거 대사에는 `AI가 영상에서 들은 말` 이라고 따로 표시합니다. 원문이 우리 손에 없어 글자 대조를 못 하기 때문입니다. 대신 **영상 속 시각이 없으면 근거에서 뺍니다.**

---

## 5. 인기 댓글을 함께 읽습니다

과제 문구는 "자막(없으면 제목·설명)과 **인기 댓글**을 읽고"입니다. 좋아요 순 상위 10개를 받아 AI에 넘기고, 시청자들이 어디에 반응했는지 참고하되 **댓글 문장은 베끼지 말고**, 근거 인용은 영상에서만 가져오게 했습니다. 모델이 댓글을 근거로 인용하면 원문 대조에서 걸러집니다. 화면에서 AI가 읽은 댓글을 펼쳐볼 수 있습니다.

---

## 6. 광고 표기를 코드에서 강제합니다

과제의 금지 사항(링크·해시태그·운명원 이용 후기 조작)에 더해, **홍보성 댓글임을 드러내는 문구**를 필수 규칙으로 넣었습니다.

표시광고법상 경제적 이해관계가 있는 추천은 그 사실을 공개해야 합니다. 시청자인 척 특정 업체를 권하는 댓글은 기만적 표시·광고에 해당할 수 있습니다. 플랫폼 약관이 아니라 법률 문제라 운영 리스크가 다릅니다.

```
길이 40~120자          링크 금지        해시태그 금지
운명원 이용 경험 조작 금지              광고 표기 필수
AI 없이 만든 임시 문구 금지
영상당 1개             하루 10개 상한
```

어긴 게 하나라도 있으면 **게시 버튼이 꺼지고**, 버튼을 우회해도 서버가 거절합니다. 광고 표기는 `.env`의 `AGENT_REQUIRE_DISCLOSURE=false`로 끌 수 있습니다(기본 켜짐).

사람이 초안을 보고 고르는 단계도 남겨 두었습니다. 리허설에서 AI가 "친구가 운명원 사주를 보니까…"처럼 **후기에 가까운 문장**을 쓴 적이 있었는데, 키워드 규칙으로는 다 잡히지 않아 [다시 생성]으로 바꿨습니다.

---

## 7. AI가 실패하면 게시를 막습니다

AI 키가 없거나 호출이 실패하면 규칙 기반 분석기가 대신 돌아 **화면은 멈추지 않습니다.** 그런데 그때 초안 칸에 들어가는 문장은 늘 같은 틀입니다.

> 영상 내용 공감되네요. 저도 비슷한 고민이라 운명원 연애사주 한번 보고 싶어지네요. (광고)

무료 한도가 떨어진 상태에서 **이 문장이 실제로 한 번 게시됐습니다**(바로 지웠습니다). 그래서 이 틀은 게시할 수 없게 막고, 실패 이유("AI 사용량 한도를 모두 썼습니다" 등)를 화면에 띄웁니다. 사람이 직접 고쳐 쓰면 다시 게시할 수 있습니다.

모델 쪽도 겪은 대로 대비했습니다. 주 모델이 과부하(503)·하루 한도(429)·사용 불가(404, 새 프로젝트 키로는 옛 모델을 못 씀)면 대체 모델을 **차례로** 시도합니다.

## 8. 연애 주제가 아닌 영상을 걸러냅니다

연애 채널만 모았는데도 다른 주제가 섞였습니다("딸 때린 아이 찾아가서 참교육" 등). 제목(과 캐시된 자막)으로 연애 관련도를 매겨 걸러냅니다.

**RSS 설명란은 쓰지 않습니다.** 채널 고정 안내문(`#연애상담` + 상담 링크)이 붙어 있어, 점수에 넣었더니 75개 중 0개만 걸러졌습니다. 설명은 영상이 아니라 채널의 주제를 알려줄 뿐입니다. 키워드 방식이라 오탐이 남으므로 **숨기되 지우지 않습니다** — 체크를 끄면 전부 보입니다.

---

## 9. 근거 없는 인용을 화면에 띄우지 않습니다

자막이 없는 영상에서 **모델이 없는 대사를 지어내고 `0:00` 이라는 시각까지 붙인** 적이 있습니다. 지금은 인용문이 우리가 넘긴 원문(자막 또는 설명)에 실제로 있는지 대조하고, 없으면 근거에서 뺍니다. 영상을 직접 본 경우는 4번처럼 따로 표시합니다. AI가 읽은 자막 원문과 인기 댓글도 화면에서 펼쳐볼 수 있습니다.

## 운영 중 확인된 제약

| 항목 | 내용 | 대응 |
|---|---|---|
| 자막 수집 | 연속 요청 시 IP 차단, 몇 시간 지속 | 캐시 · 요청 간격 · 사전 워밍업, 막히면 AI가 영상을 직접 봄 |
| AI 한도 | 무료 등급은 모델·프로젝트마다 하루 20회 | 대체 모델 차례 시도, 실패 시 게시 차단 |
| 자동 입력 게시 | 유튜브가 일부 댓글을 숨김(작성자에게만 잠깐 보임) | 공개 여부를 API로 대조해 표시 |
| OAuth 토큰 | 테스트 상태에서 7일 후 만료 | 재인증 안내, 만료도 실패로 기록 |
| 공개 배포 | `youtube.force-ssl` 은 민감 범위라 구글 심사 필요 | 현재 범위에서는 테스트 상태로 충분 |

## 하지 않은 것

- **자동화 감지를 피하는 기능** — 자동화 흔적 숨기기, 사람처럼 보이려는 무작위 입력 속도
- **한 영상에 여러 계정으로 다는 것** — 서로 다른 시청자인 척하는 구조

계정 배정과 한 글자씩 입력은 과제 요구라 만들었지만, 위 두 가지는 제품의 성격을 "홍보 도구"에서 "플랫폼 정책을 우회하는 도구"로 바꿉니다. 영상당 계정 하나, 계정 합계 하루 10개, 광고 표기를 코드에서 강제하는 것도 같은 이유입니다.
